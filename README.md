## Описание решений

### 230B — T-primes

**Ссылка:** [Codeforces 230B](https://codeforces.com/problemset/problem/230/B)

**Задача:** необходимо определить, является ли каждое заданное число T-простым, то есть имеет ли оно ровно три различных положительных делителя.

**Идея решения:**

Число имеет ровно три положительных делителя тогда и только тогда, когда оно является квадратом простого числа.

Поэтому для каждого числа:
1. Вычисляется целочисленный квадратный корень.
2. Проверяется, является ли исходное число точным квадратом этого корня.
3. Проверяется простота квадратного корня.
4. Выводится `YES` или `NO`.

**Проверка простоты:**

Для проверки числа на простоту достаточно перебрать делители от 2 до квадратного корня проверяемого числа.

**Сложность:**

Для одного числа `x`:
- Время: `O(√x)`.
- Дополнительная память: `O(1)`.

Для `n` чисел общая оценка составляет `O(n√M)`, где `M` — максимальное значение входного числа.

### 279B — Books

**Ссылка:** [Codeforces 279B](https://codeforces.com/problemset/problem/279/B)

**Задача:** необходимо найти максимальное количество книг, которые можно прочитать подряд, не превышая заданное время.

**Идея решения:**

Используется метод двух указателей — скользящее окно.

Два указателя задают текущий непрерывный отрезок книг. Поддерживается сумма времени чтения книг внутри этого отрезка.

Если сумма превышает доступное время, левый указатель перемещается вправо, пока условие снова не будет выполнено.

На каждом шаге обновляется максимальная длина подходящего отрезка.

**Алгоритм:**

1. Считать количество книг, доступное время и массив времени чтения.
2. Инициализировать два указателя и текущую сумму.
3. Перемещать правый указатель, добавляя время чтения очередной книги.
4. Если сумма превышает ограничение, перемещать левый указатель.
5. Обновлять максимальное количество книг.
6. Вывести результат.

**Сложность:**

- Время: `O(n)`, поскольку каждый указатель проходит массив не более одного раза.
- Дополнительная память: `O(n)` при хранении массива входных данных; `O(1)` сверх массива.

### 698A — Vacations

**Ссылка:** [Codeforces 698A](https://codeforces.com/problemset/problem/698/A)

**Задача:** необходимо минимизировать количество дней отдыха. Каждый день можно отдыхать, заниматься спортом или участвовать в соревнованиях, если соответствующая активность доступна. Нельзя выполнять одну и ту же активность два дня подряд.

**Идея решения:**

Задача решается динамическим программированием.

Для каждого дня рассматриваются три состояния:

- `dp[i][0]` — минимальное количество дней отдыха к дню `i`, если в этот день выбран отдых.
- `dp[i][1]` — минимальное количество дней отдыха, если выбран спорт.
- `dp[i][2]` — минимальное количество дней отдыха, если выбраны соревнования.

Переходы зависят от доступных активностей в текущий день.

Если выбран отдых, к минимальному предыдущему состоянию добавляется один день отдыха.

Если выбран спорт или соревнования, предыдущий день не должен содержать ту же активность.

**Алгоритм:**

1. Считать количество дней и доступные активности.
2. Инициализировать состояния первого дня.
3. Для каждого следующего дня вычислить три возможных состояния.
4. Запретить переходы, нарушающие условие повторения активности.
5. Получить ответ как минимум из трёх состояний последнего дня.

**Сложность:**

- Время: `O(n)`.
- Дополнительная память: `O(n)` при хранении всей таблицы ДП.
- Память можно уменьшить до `O(1)`, если хранить только состояния предыдущего дня.

### 479C — Exams

**Ссылка:** [Codeforces 479C](https://codeforces.com/problemset/problem/479/C)

**Задача:** необходимо определить минимальный день завершения всех экзаменов с учётом допустимых дат и порядка записей в зачётке.

**Идея решения:**

Используется сортировка и жадный алгоритм.

Сначала экзамены сортируются по первой допустимой дате, а при равенстве — по второй.

Затем экзамены рассматриваются по порядку. Для каждого экзамена выбирается наиболее ранняя допустимая дата, которая не меньше даты предыдущего экзамена.

Если вторая дата экзамена подходит, выбирается она. В противном случае выбирается первая дата.

**Алгоритм:**

1. Считать количество экзаменов и допустимые даты.
2. Отсортировать пары дат.
3. Инициализировать день предыдущего экзамена.
4. Последовательно обработать все экзамены.
5. Выбрать допустимую дату с учётом предыдущего экзамена.
6. Вывести день последнего экзамена.

**Сложность:**

- Время: `O(n log n)` из-за сортировки.
- Дополнительная память: `O(n)` при хранении массива экзаменов; `O(1)` сверх него.

### 1195C — Basketball Exercise

**Ссылка:** [Codeforces 1195C](https://codeforces.com/problemset/problem/1195/C)

**Задача:** необходимо выбрать игроков из двух рядов так, чтобы сумма их ростов была максимальной. При этом индексы выбранных столбцов должны строго возрастать, а соседние выбранные игроки должны находиться в разных рядах. Столбцы можно пропускать.

**Идея решения:**

Задача решается динамическим программированием.

Используются три состояния:

- `dp[i][0]` — максимальная сумма, если в столбце `i` выбран игрок верхнего ряда.
- `dp[i][1]` — максимальная сумма, если в столбце `i` выбран игрок нижнего ряда.
- `dp[i][2]` — максимальная сумма, если столбец `i` пропущен.

При выборе игрока из верхнего ряда предыдущий выбранный игрок должен находиться в нижнем ряду или не быть выбранным в предыдущем столбце.

Аналогично для нижнего ряда.

Состояние пропуска позволяет не выбирать игрока в текущем столбце.

**Алгоритм:**

1. Считать количество столбцов и рост игроков в двух рядах.
2. Инициализировать состояния первого столбца.
3. Для каждого следующего столбца вычислить максимальные значения трёх состояний.
4. Учесть возможность пропуска столбца.
5. Вывести максимальное значение среди состояний последнего столбца.

**Сложность:**

- Время: `O(n)`.
- Дополнительная память: `O(n)` при хранении таблицы ДП.
- Память можно уменьшить до `O(1)`, если хранить только состояния предыдущего столбца.

## Подробный разбор динамического программирования

### 698A — Vacations

**Состояния**

Для каждого дня хранятся три значения:

- `dp[i][0]` — отдых в день `i`.
- `dp[i][1]` — спорт в день `i`.
- `dp[i][2]` — соревнования в день `i`.

Каждое значение показывает минимальное количество дней отдыха на отрезке от первого дня до текущего.

**База**

Для первого дня:

- Если доступен отдых, состояние отдыха равно 1.
- Если доступен спорт, состояние спорта равно 0.
- Если доступны соревнования, состояние соревнований равно 0.
- Недоступные активности получают значение бесконечности.

**Переходы**

Если в текущий день выбран отдых:

`dp[i][0] = min(dp[i-1][0], dp[i-1][1], dp[i-1][2]) + 1`

Если выбран спорт:

`dp[i][1] = min(dp[i-1][0], dp[i-1][2])`

Если выбраны соревнования:

`dp[i][2] = min(dp[i-1][0], dp[i-1][1])`

Переходы для спорта и соревнований выполняются только тогда, когда соответствующая активность доступна.

**Получение ответа**

Ответом является минимум из трёх состояний последнего дня.

**Обоснование корректности**

В каждом состоянии рассматриваются все допустимые варианты завершения текущего дня.

При выборе спорта исключается спорт в предыдущий день. При выборе соревнований исключаются соревнования в предыдущий день. Отдых не накладывает ограничений на предыдущую активность.

Таким образом, все допустимые последовательности учитываются, а недопустимые исключаются. Выбор минимума гарантирует минимальное количество дней отдыха.

**Почему жадный выбор может ошибаться**

Если каждый день выбирать первую доступную активность, можно получить неоптимальную последовательность.

Например, для входных данных:

```text
4
1 3 2 0
```

Если в первый день выбрать отдых, во второй — спорт, в третий — соревнования, в четвёртый снова отдых, получится 2 дня отдыха.

Оптимальный результат также необходимо получать сравнением всех допустимых состояний, а не фиксированным локальным правилом.

### 1195C — Basketball Exercise

**Состояния**

Для каждого столбца:

- `dp[i][0]` — максимальная сумма при выборе верхнего игрока.
- `dp[i][1]` — максимальная сумма при выборе нижнего игрока.
- `dp[i][2]` — максимальная сумма при пропуске текущего столбца.

**База**

Перед обработкой первого столбца сумма выбранных игроков равна нулю.

Для первого столбца можно выбрать верхнего игрока, нижнего игрока или пропустить столбец.

**Переходы**

Если выбран верхний игрок:

`dp[i][0] = top[i] + max(dp[i-1][1], dp[i-1][2])`

Если выбран нижний игрок:

`dp[i][1] = bottom[i] + max(dp[i-1][0], dp[i-1][2])`

Если столбец пропущен:

`dp[i][2] = max(dp[i-1][0], dp[i-1][1], dp[i-1][2])`

**Получение ответа**

Ответ — максимум из трёх состояний последнего столбца.

**Обоснование корректности**

Переходы рассматривают все допустимые варианты обработки текущего столбца.

При выборе верхнего игрока предыдущий выбранный игрок может быть только из нижнего ряда или отсутствовать. Аналогичное условие действует для нижнего ряда.

Состояние пропуска позволяет сохранить лучший результат, не выбирая игрока из текущего столбца.

Таким образом, порядок индексов сохраняется, а два соседних выбранных игрока не могут находиться в одном ряду.

**Числовой тип**

Для хранения сумм используется целочисленный тип, способный вместить максимальную сумму ростов всех выбранных игроков. При необходимости следует использовать `long long`.
